Les limites à l’épreuve

Un hook qui compte le bytecode ne suffit pas à limiter tous les scripts Lua. Voici des reproductions exécutables, côte à côte.

La colonne amont utilise Fengari 0.1.5, tel que publié sur npm, avec un hook hôte de 20 000 instructions. Pyroeis utilise son API limits avec le même budget, 200 ms, un plafond de 1 Mio par allocation et 4 Mio cumulés par appel.

Les deux moteurs tournent dans des Web Workers séparés. Un worker occupé plus de 1,5 seconde est arrêté par la page ; le chronomètre commence après le chargement du moteur. Aucun script ne reçoit de pont JavaScript, de fichier ou d’accès à une autre application.

Ce que ces cas démontrent

    
Les recherches de motifs et table.move peuvent monopoliser une fonction native sans rendre la main au hook de bytecode. Une erreur de hook peut aussi être attrapée par pcall, ou déclencher un gestionnaire xpcall sans contrôle. Cela devient un risque de déni de service lorsque l’hôte exécute des scripts non fiables en se reposant sur ce seul hook.

    
Fengari amont ne fournit pas l’API sandbox ou limits de Pyroeis. L’adaptateur utilisé ici retire les bibliothèques sensibles et ajoute un hook ; il ne prétend pas être un sandbox officiel Fengari. Le cas d’allocation illustre une protection ajoutée par Pyroeis, plutôt qu’un engagement de sécurité de l’amont.

    
Les anciens défauts de @datamoc/fengari (helpers de fichiers exposés, limites sur les chemins globaux et sur Coroutine#close) concernent notre ancien paquet et sont décrits dans son historique. Ils ne sont pas attribués à Fengari 0.1.5. Ces reproductions ne constituent pas un audit exhaustif.

    
Sources, versions et limites de la protection
Scripts Lua exacts · Exécution dans le worker · Adaptateur amont · Versions et empreintes des archives npm · Tests de régression.
Le bundle amont conserve le code de la VM et remplace uniquement process.env.FENGARICONF par undefined au build pour charger la configuration par défaut dans le navigateur. Les modules Node sont exclus du chemin d’exécution.
Les plafonds d’allocation couvrent les allocations internes de chaînes et buffers instrumentées, pas toute la mémoire JavaScript ni les tables Lua. D’autres fonctions natives, comme le tri et certains formats, ne sont pas interrompues au milieu de leur travail. Une isolation extérieure reste nécessaire pour borner l’ensemble d’un programme et ses callbacks hôtes.
