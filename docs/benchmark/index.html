Pyroeis vs JavaScript

Fengari 0.1.5, Pyroeis interpreted, compiled numeric Lua and native JavaScript running the same algorithms. Everything runs in your browser, right now.

Pyroeis normally interprets Lua bytecode in JavaScript. Its optional numeric compiler converts supported functions and complete numeric loops into JavaScript that your browser can optimize. This page measures both execution modes against hand-written JavaScript. To move a Lua program to JavaScript for good, try the Lua to JavaScript translator. Algorithms outside the supported subset are marked Interpreter fallback.

Method

Upstream Fengari uses 32-bit integers while Pyroeis supports a wider integer range. These inputs keep integer intermediates within the shared signed 32-bit range; the pseudo-random generator explicitly uses floats for its larger products. No checksum differences are hidden or excluded.

Each benchmark uses the same input size and returns a checksum; the last column checks all four measured modes. The upstream adapter calls the Fengari 0.1.5 C API and includes its host call overhead, just as Pyroeis timings include vm.call; this is a comparison of these integrations, not an isolated measurement of interpreter internals. Every mode gets an untimed warm-up. Each timed sample repeats the function for at least 80 ms, then divides by the number of calls; the median sample is reported. This keeps short expressions measurable despite browser clock rounding. Interpreter times include vm.call overhead; compiled times include the guards in the callable returned by vm.compile.

Lua loading and compilation happen outside the timed samples. Numeric compilation supports arithmetic, locals and integer numeric for loops; calls, tables and branches use the interpreter. Fallback rows show no compiled timing or speedup, and are excluded from the compiler summary. A browser policy that blocks dynamic JavaScript compilation also causes fallback. Pyroeis opens only base, string, table and math. The upstream adapter opens the standard libraries and removes debug, io, os, package and file loaders. No execution budgets are enabled during timings; numeric compilation is intentionally disabled under limits.
